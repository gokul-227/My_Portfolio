GT Connect – Healthcare Application Modernization on AWS

A cloud-native transformation project focused on migrating a legacy healthcare application (AMT) to AWS while rebuilding core functionalities using scalable and serverless architecture.

  1. Home
  2. Project Details

Project Information

  • Project: GT Connect – AWS Modernization
  • Client: Lilly, USA
  • Duration: Aug 2022 – Mar 2023
  • Domain: Healthcare
  • Access: Enterprise (Confidential)

Project Overview

GT Connect is a modernization initiative that migrated the legacy AMT healthcare application into AWS, while rebuilding its core modules such as file upload, transaction processing, and user management.

The system leverages AWS serverless and container-based services to deliver scalability, automation, and improved performance.

Project Description

The legacy AMT application was re-engineered into a modern cloud-native system on AWS. Core functionalities like file ingestion, transaction management, and search capabilities were redesigned using scalable and event-driven architecture.

The system ensures secure data processing, validation, logging, and notification mechanisms, improving operational efficiency and user experience.

Key Features

  • Migration of legacy AMT application to AWS cloud
  • File upload and validation using AWS Glue
  • Transaction management (Create & Search APIs)
  • Email notifications using AWS SES
  • Centralized logging and monitoring system
  • Serverless and container-based architecture

Technologies Used

Cloud: AWS (S3, Lambda, Glue, EventBridge, ECS Fargate, SES, RDS)
Processing: PySpark, Python
Database: PostgreSQL (RDS)
DevOps: GitHub, CodePipeline, CloudFormation (YAML)
Tools: SQL, JIRA

Architecture Highlights

  • File upload triggers EventBridge events
  • Lambda functions initiate Glue jobs
  • PySpark validates and processes Excel data
  • Processed data stored in PostgreSQL (RDS)
  • APIs built for transaction creation and retrieval
  • SES used for sending validation and job status emails
  • Logs and job status stored in database for tracking

Roles & Responsibilities

  • Gathered requirements and analyzed legacy AMT application
  • Designed AWS architecture, ER diagrams, and data flow diagrams
  • Performed POCs using AWS Glue and ECS Fargate
  • Created CloudFormation YAML templates for infrastructure
  • Configured IAM roles, S3, Lambda, Glue, EventBridge, SES, and RDS
  • Developed Lambda functions for event-driven workflows
  • Built PySpark scripts for file validation and ingestion
  • Implemented email notification system using SES
  • Developed APIs for transaction processing and search functionality
  • Stored logs and job status in PostgreSQL
  • Deployed solutions using AWS CodePipeline
  • Maintained documentation and conducted knowledge transfer sessions

Challenges & Solutions

  • Challenge: Migrating complex legacy workflows
    Solution: Rebuilt modules using microservices and serverless architecture
  • Challenge: Ensuring data validation accuracy
    Solution: Implemented robust PySpark validation logic
  • Challenge: Real-time processing and notifications
    Solution: Integrated EventBridge, Lambda, and SES for automation

Impact & Outcome
